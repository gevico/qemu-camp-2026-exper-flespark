# G233 Linux Boot Test Fixtures

This directory contains fixtures and scripts for testing Linux boot on the G233 board (Advanced Experiment 3).

## Analysis: Missing Components for Linux Boot

Based on analysis of the G233 board implementation (`hw/riscv/g233.c`) and comparison with the QEMU `virt` reference board, the following components are **already present** and the following are **missing or need modification** for Linux boot:

### Present and Working

| Component | Address | Status |
|-----------|---------|--------|
| CPU (riscv64 hart array) | - | OK |
| DRAM | 0x80000000 | OK |
| CLINT/ACLINT (timer + IPI) | 0x02000000 | OK |
| PLIC (interrupt controller) | 0x0C000000 | OK |
| virtio-mmio (8 slots) | 0x10100000 | OK |
| SiFive Test (reset/poweroff) | 0x100000 | OK |
| Goldfish RTC | 0x101000 | OK |
| PCIe (GPEX) | 0x30000000 | OK |
| GPIO | 0x10012000 | OK |
| PWM | 0x10015000 | OK |
| WDT | 0x10010000 | OK |
| SPI + Flash | 0x10018000 | OK |
| FDT generation (create_fdt) | - | OK (includes CPUs, memory, UART, virtio, PLIC, CLINT, etc.) |

### Missing / Needs Modification

#### 1. UART Type Mismatch (CRITICAL)

**Problem**: The G233 board currently uses a **PL011** (ARM PrimeCell UART), but the default OpenSBI firmware (`-bios default`) only includes drivers for **ns16550a** (8250-compatible) UARTs. This means OpenSBI cannot produce console output on the G233 board.

**Current code** (`hw/riscv/g233.c`):
```c
// Line 1773: Uses PL011
pl011_create(s->memmap[VIRT_UART0].base,
             qdev_get_gpio_in(mmio_irqchip, UART0_IRQ),
             serial_hd(0));

// Line 983: DTB says "pl011"
qemu_fdt_setprop_string(ms->fdt, name, "compatible", "pl011");
```

**Fix**: Switch to ns16550a UART for OpenSBI compatibility:
```c
// In virt_machine_init(), replace pl011_create with:
serial_mm_init(system_memory, s->memmap[VIRT_UART0].base,
    0, qdev_get_gpio_in(mmio_irqchip, UART0_IRQ), 399193,
    serial_hd(0), DEVICE_LITTLE_ENDIAN);

// In create_fdt_uart(), change compatible:
qemu_fdt_setprop_string(ms->fdt, name, "compatible", "ns16550a");
```

The ns16550a driver is also what Linux uses for the `console=ttyS0` boot parameter. With PL011, you'd need `console=ttyAMA0` and a custom OpenSBI build.

#### 2. Kernel bootargs in DTB (RECOMMENDED)

The `create_fdt` function should set default bootargs for Linux boot:
```c
qemu_fdt_setprop_string(ms->fdt, "/chosen", "bootargs",
    "root=/dev/vda rw console=ttyS0 earlycon");
```

Currently the `/chosen` node exists but has no `bootargs` property. Linux can still receive bootargs via `-append`, but having defaults in the DTB is better.

## Files

- `prepare-fixture.sh` — Downloads or builds Linux kernel Image + creates minimal initramfs rootfs
- `Image` — Linux kernel (riscv64) — **generated by prepare-fixture.sh**
- `rootfs.cpio.gz` — Minimal initramfs — **generated by prepare-fixture.sh**
- `rootfs.ext4` — ext4 filesystem for virtio-blk testing — **optional, generated by prepare-fixture.sh**

## Usage

### Step 1: Prepare fixtures

```bash
cd tests/gevico/qtest/linux-fixture
bash prepare-fixture.sh
```

This requires either:
- A RISC-V cross-compiler (`riscv64-linux-gnu-gcc`) for building kernel and init, OR
- Network access to download pre-built kernel images

### Step 2: Fix UART type (see above)

### Step 3: Run the Linux boot test

```bash
# From build directory
make -C build/tests/gevico/qtest/ run-linux-boot

# Or directly:
export QTEST_QEMU_BINARY=./build/qemu-system-riscv64
./build/tests/gevico/qtest/test-linux-boot
```

## Test Cases

| Test | Description | Requires Fixtures |
|------|-------------|-------------------|
| `prerequisites` | Verifies all MMIO devices exist | No |
| `virtio-for-linux` | Verifies virtio-blk/net can attach | No |
| `opensbi` | Boots OpenSBI and checks serial output | No (but needs UART fix) |
| `initrd` | Full Linux boot with initrd | Yes |
| `dtb` | Verifies DTB completeness via kernel boot | Yes |
| `virtio-blk` | Linux boot with virtio-blk device | Yes + ext4 |

## Boot Command Reference

Once the UART is fixed, Linux should boot with:
```bash
qemu-system-riscv64 -M g233 -nographic \
    -bios default -kernel Image \
    -append "root=/dev/vda rw console=ttyS0 earlycon" \
    -drive file=rootfs.ext4,format=raw,if=none,id=hd0 \
    -device virtio-blk-device,drive=hd0
```
